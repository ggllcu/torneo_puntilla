# La Puntilla Tournament App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public, SSR, auto-refreshing tournament calendar with a referee scoring screen, backed by emdash CMS on Cloudflare Workers + D1, live before Sat 17 Oct 2026 09:00 (Atlantic/Canary).

**Architecture:** emdash `cloudflare:starter` Astro project. All tournament data lives in emdash collections, defined and filled through `seed/seed.json`. That file is generated by a script from one typed data module and applied by the emdash setup wizard ("include content"). Pure logic (scoring, schedule, standings, display) sits in `src/lib/*` with unit tests. One data module wraps the emdash read and write APIs. Pages are thin Astro templates, and two small vanilla-TS client scripts handle the referee screen and the live refresh.

**Tech Stack:** Astro (SSR, `@astrojs/cloudflare`), emdash 1.3.x + `@emdash-cms/cloudflare` (D1 `DB`, R2 `MEDIA`), TypeScript, Vitest, Wrangler.

**Spec:** `docs/superpowers/specs/2026-10-16-puntilla-tournament-app-design.md`. Read it; §5 holds the full schedule.

## Global Constraints

- English only. Categories display as "Men's", "Women's", "Mixed"; URL values `mens`, `womens`, `mixed`.
- Tabs: "Qualifiers" (= Saturday matches, URL `qualifiers`) and "Finals" (= Sunday matches, URL `finals`).
- Time zone for every displayed time: `Atlantic/Canary`. In Oct 2026 that is UTC+1, so 09:00 local = 08:00Z.
- Scoring: a set goes to 21, or 15 for the 3rd set of a best-of-3; win by 2; no cap. Only the 1st/2nd place Final is best of 3.
- Displayed match time = `time_override` ?? `session.starts_at + (slot − 1) × session.slot_minutes` (default 20).
- Public site: no auth. CMS: emdash admin, one admin user.
- Tournament pages must never be cached: `Cache-Control: no-store`.
- `status` is a reserved emdash field slug, so the match state field is `match_state` (`scheduled` | `finished`).
- emdash reference fields cannot be filtered or sorted, and they are not in `entry.data`. Load them with `getEmDashEntry(collection, id, { references: {...} })`.
- Minimal build: no auto-advancement, walkover/penalty UI, timeouts, i18n or visual polish beyond clean and readable on mobile.

## Review Focus

1. **Deuce past 21** (e.g. 25–23): the set must end only on a 2-point lead, with no cap. Pinned in Task 2 (`addPoint` deuce test).
2. **Referee taps − right after a best-of-3 set auto-advanced to 0–0:** the previous set must reopen, not get stuck. Pinned in Task 2 (`removePoint` reopen test).
3. **Admin-entered results that break the rules** (21–0 walkover, a 0–0 placeholder, a tie): the calendar and standings must not crash or invent a winner. Pinned in Task 3 (`winnerOf` tie → null; standings ignore unfinished/tied).
4. **Times on a UTC server:** the calendar must show Canary local time. Pinned in Task 3 (`formatTime` test).
5. **Submit for a match with a placeholder team or an invalid score:** the request must be rejected with 400. Pinned in Task 2 (`checkSubmission` tests).

### Task 2: Scoring rules and referee state machine

**Files:**
- Create: `src/lib/scoring.ts`, `tests/scoring.test.ts`

**Interfaces:**
- Consumes: `Format`, `SetScore`, `MatchView` from `src/lib/types.ts`
- Produces:
  ```ts
  export type ScoreState = { completed: SetScore[]; current: SetScore };
  export const emptyState: () => ScoreState;
  export function setTarget(format: Format, setIndex: number): number;          // 21, or 15 for index 2 of best_of_3
  export function setWinner(set: SetScore, target: number): 1 | 2 | null;      // ≥ target and lead ≥ 2
  export function addPoint(s: ScoreState, team: 1 | 2, format: Format): ScoreState;
  export function removePoint(s: ScoreState, team: 1 | 2, format: Format): ScoreState;
  export function matchOutcome(s: ScoreState, format: Format): { finished: boolean; winner: 1 | 2 | null; sets: SetScore[] };
  export function isValidResult(format: Format, sets: SetScore[]): boolean;
  export function checkSubmission(match: Pick<MatchView, "team1" | "team2" | "format">, sets: unknown): string | null; // null = ok, else error message
  ```
  - `addPoint`: increments `current`. If that wins the current set **and** the match is not finished, push `current` to `completed` and reset `current` to 0–0. A match-winning point never advances.
  - `removePoint`: if `current` is 0–0 and `completed` is non-empty, pop the last completed set back into `current` first, then decrement `team` (never below 0).
  - `matchOutcome.sets` = `completed` plus `current` (current is omitted when it is 0–0 and completed is non-empty).
  - `checkSubmission` messages: `"Teams not assigned"`, `"Invalid score"`.

### Task 6: Referee screen

**Files:**
- Create: `src/pages/referee/[id].astro`, `src/scripts/referee.ts`

**Interfaces:**
- Consumes: `loadMatch` (Task 4); `emptyState`, `addPoint`, `removePoint`, `matchOutcome`, `setTarget` (Task 2); `formatScore`, `roundLabel` (Task 3); endpoint (Task 4)
- Produces: page `/referee/<id>`. A missing match → 404. A finished match or one with a placeholder team → a message plus a link back to the calendar (no scoring UI).

Behaviour:
- The server renders match info (round, court, time, team names) and passes `{ id, format, team1Name, team2Name, backUrl }` to the client via `data-*` attributes. `backUrl` = `/<category>/<qualifiers|finals>#match-<id>`.
- Layout: a three-column grid. The left column (team 1) has a big **+** and a smaller **−** below it; the centre shows the score `7 - 5`, and for best of 3 also "Set N" and sets won; the right column mirrors the left for team 2. Buttons must be large enough for thumbs.
- Every change saves state to `localStorage` key `ref:<id>` (wrapped in try/catch) and restores it on load.
- When `matchOutcome(...).finished` becomes true, open a modal "Submit Score" showing `formatScore(sets)`, with **Cancel** (closes it; scoring continues and the modal reopens the next time the match is finished after a change) and **Submit** (POST `{ sets }`). On 200, clear `ref:<id>` and `location.href = backUrl`. Otherwise show the error text in the modal and keep the state.
